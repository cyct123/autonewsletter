认证与配置分层设计

HTTP Basic Auth 保护所有管理入口，配置按性质分层存储

认证方案

HTTP Basic Auth 覆盖范围
❌ 改造前（无保护）
GET /admin/* → 直接访问
POST /trigger → 直接访问

✅ 改造后（Basic Auth）
GET /admin/* → 需要用户名+密码
POST /trigger → 需要用户名+密码

配置（写入 .env）
ADMIN_USER=admin
ADMIN_PASS=your_password

配置分层

留在 .env（基础设施/密钥）
DATABASE_URL
REDIS_URL
DEEPSEEK_API_KEY
OPENAI_API_KEY
SMTP_PASS
ADMIN_USER / ADMIN_PASS
重启才能更改，不暴露给后台
迁移到数据库（运营配置）
weekly_cron
max_items_per_run（默认值）
force_recent
log_level
ai_model（deepseek/openai）
后台实时修改，无需重启

app_config 表结构（强类型字段，非万能 key-value）

system_config 表
weekly_cron       String   "0 9 * * 3"
ai_model         String   "deepseek" | "openai"
max_items        Integer 5
force_recent     Boolean False
log_level        String   "info"
单行表（id=1），后台渲染为设置页而非列表
