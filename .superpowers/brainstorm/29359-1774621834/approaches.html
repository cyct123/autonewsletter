管理后台实现方案

三种方案各有侧重，请选择最适合你的

A

SQLAdmin（推荐）

基于 SQLAdmin 库，自动从 SQLAlchemy 模型生成表格式管理界面，挂载到 /admin 路径。配置存数据库，AI/定时任务配置新增 app_config 表动态读取。

优点

  • 代码量极少，自动生成 CRUD
  • 与现有 SQLAlchemy 模型无缝集成
  • 支持自定义操作按钮（触发 pipeline）

缺点

  • 界面样式固定，定制性有限
  • 复杂查询需额外配置
B

Starlette Admin

功能更丰富的 Admin 框架，支持更灵活的自定义视图、表单验证和文件上传。配置存数据库，动态读取。

优点

  • 功能更全面（批量操作、导出等）
  • UI 更现代（Bootstrap 5）
  • 支持自定义页面

缺点

  • 配置稍复杂
  • 文档不如 SQLAdmin 完善
C

自定义 FastAPI + Jinja2

纯手写后台，FastAPI 路由 + Jinja2 模板渲染 HTML 页面，完全控制每个页面的交互逻辑。

优点

  • 完全定制，UI 随意设计
  • 无额外依赖约束

缺点

  • 开发量大（每个 CRUD 都要手写）
  • 维护成本高
